# PixelDiT-QDM Halo2 验证记录

2026-10-21，`linear-pid` 环境，node01 四张 A40，原生 1K 多长宽比。以下为恢复远程 RoPE 之前的 NoPE 版本记录。所有阶段均执行真实图片、Gemma 缓存、完整 14 层 MMDiT 和两层 PiT，累积为 1。

| 阶段 | 每卡 batch | 有效 batch | 测试更新数 | 可训练参数 | 峰值显存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 4 | 16 | 2 | 37,396,352 | 6.16 GiB |
| A2 | 8 | 32 | 2 | 37,396,352 | 12.99 GiB |
| B | 8 | 32 | 2 | 60,019,208 | 13.47 GiB |

- 官方 checkpoint 的 385 个主干张量严格加载，共 1,302,470,787 参数；6 个辅助 REPA projector 张量单独识别，不进入网络。
- 6 项 CPU 测试通过：教师路径、A1 层输入/梯度、LoRA 零增量与冻结参数、严格加载/阶段 batch、恢复下一次更新、原生空文本替换。CPU 恢复下一次更新逐位一致。
- B 从第 1 步保存状态恢复到第 2 步，优化器 step、scheduler、数据进度及四个 rank 的 CPU/CUDA RNG 状态一致。与不中断运行相比，参数最大绝对差 `2.92e-6`；GPU 内核未配置为确定性执行，不承诺逐位相同。
- 与原始 PixelDiT 源码比较真实 1024² 输入：FP32 最终预测相对 L2 误差 `1.23e-6`。BF16 不逐位一致，随机输入相对差约 `1.11%`，涉及不同设备上的频率预计算与有限精度累积；本实验师生使用同一套本地主干实现。
- 原生 50 步、CFG 2.75、shift 4 的 prompt 推理及固定画廊通过。画廊仅使用文本条件与像素噪声，不使用包内图像 latent。原始 1K 参考图能够正常生成小孩与狗的场景。
- 控制器通过两轮独立进程测试，确认训练子进程和控制器 PID 均更新；状态保存后继续下一轮，而非保持旧 PID 的 `exec`。

以上是代码通过性与恢复验证，两个更新不能用来判断 QDM 的质量恢复。显存仅对应测试输入；耗时受同机其他任务及首次解码影响，不作为稳定吞吐基准。早期 2K/4K 接口探测也不构成这些分辨率下的质量验证。

可以使用以下短程命令检查同样的三个阶段；正式训练命令见 [运行说明](pixeldit-qdm.md)。资源环境变量按运行说明设置。

```bash
conda activate linear-pid
GPU_IDS=0,1,2,3 CPU_THREADS=1 bash scripts/train_pixeldit_qdm.sh \
  --stage all --no-remote-rope --a1-steps 2 --a2-steps 2 --b-steps 2 \
  --save-steps 1 --validation-steps 0 --teacher-checkpoint "$PIXELDIT_BASE" \
  --workers 4 --threads 1 --output-root outputs/pixeldit-qdm-preflight
```

## 恢复远程 RoPE 后的检查

同日在上述四卡和 1K 设置下，图像 Q/K 在记忆统计及读取前加入原始全图二维 RoPE，其他算法及优化配置保持一致。

| 阶段 | 每卡 batch | 有效 batch | 测试更新数 | 峰值显存 |
| --- | ---: | ---: | ---: | ---: |
| A1 | 4 | 16 | 2 | 6.16 GiB |
| A2 | 8 | 32 | 2 | 12.99 GiB |
| B | 8 | 32 | 2 | 13.47 GiB |

- 10 项 CPU 检查通过，覆盖非正方形四象限求解与梯度的直接参考、教师及局部分支不变、远程 RoPE 对学生输出生效、LoRA 零增量、冻结参数、恢复下一次更新及后台阶段切换参数传递。
- 四卡 A1 从第 1 步恢复至第 2 步，随后串行切换至 A2、B；检查各阶段 optimizer step、scheduler、累计 step、RoPE 配置及有效 batch，均符合预期。临时测试权重在检查后删除。
- 未出现 OOM 或非有限 loss。DDP 对 depthwise 卷积报告梯度 stride 与 bucket view 不同的性能警告，训练正常完成；该警告尚未做性能优化。
- 当前只验证代码及恢复流程，未验证此改动是否能改善重复人脸或空间错位。正式实验从原始 PixelDiT 权重开始，保留原 NoPE 输出作对照。

使用前述短程命令时，将 `--no-remote-rope` 改为 `--remote-rope` 并使用独立输出目录，即可检查此版本。正式后台命令见 [运行说明](pixeldit-qdm.md)。

## 合成数据 A1 入口检查

- 500 步、四卡、每卡 bs4、累积1的原始抽样计划共8,000次曝光、6,602个不同样本 ID，已保存全部500步的顺序和重复关系。
- 四卡使用原始 Full Attention PixelDiT、已有 Gemma 缓存、50步、CFG 2.75、shift 4，实际生成16张1024×1024图像，没有 OOM。重跑成功跳过这16张，未重新加载 DiT。
- 使用这16张合成图、相同样本 ID 和缓存，通过四卡 A1 单步前反向和保存；有效 batch16，峰值显存5.48 GiB，优化器和 scheduler 均到第1步。临时训练权重已删除，生成图保留为正式数据集的一部分。
- 13项 CPU 检查通过，新增检查覆盖原 caption 抽样顺序、跨 rank 拆分、图像完整发布、损坏图片拦截和逐图噪声 seed 与生成 batch 无关。
- 后台控制器在生成阶段、尚无训练 checkpoint 时通过两轮进程更新测试；能根据已生成图像数量识别进展，更新控制器与子进程 PID。完整任务生成完毕后仅启动 A1。

这些检查只证明入口可运行；合成数据是否改善迁移质量，需要等待正式 A1 的固定样本验证。
